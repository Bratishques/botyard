# Botyard Admin

Админка платформы Botyard для операторов: назначения (Dokploy-инстансы), клиенты, каталог роботов,
развёртывания с историей операций. Работает только с админ-API из `../api`, контракт —
[api-contract.md](../api/docs/api-contract.md), схемы тел и формы ответов — `@botyard/contract`.

Статус: этап 4, см. [план](../api/docs/roadmap.md). Нет журнала аудита и смены конфига развёртывания: в API пока нет
ручек.

## Запуск

Нужен запущенный api на `http://localhost:4000` (см. корневой README) и оператор (`bun run operator:create` в `api`).

```bash
bun install                      # в корне монорепо
cd admin
bun run dev                      # http://localhost:5173, API — через прокси /api → :4000
ADMIN_PORT=5181 BOTYARD_API_URL=http://localhost:4000 bun run dev   # другой порт или адрес API
bun run build                    # статическая сборка в dist/
bun run check                    # из корня: lint, typecheck, test всех пакетов
```

Админка ходит в API с **того же origin**: dev-сервер Vite проксирует `/api/*` на api, срезая префикс. Cookie
сессии `SameSite=Strict` и требование JSON в изменяющих запросах защищают от CSRF только так; CORS api не
открывает. В проде статику `dist/` и `/api` должен отдавать один обратный прокси с тем же правилом.

## Экраны

| Экран | Что делает |
|---|---|
| Вход | Почта и пароль; 401 на любом запросе возвращает сюда с возвратом на прежнюю страницу |
| Назначения | Список со статусом проверки; добавить (адрес и ключ → `preview` → выбор окружения и сервера), изменить, проверить связь, включить и выключить. Ключ только вводится, показывается подсказка `••••abcd` |
| Клиенты | Список; создать в песочнице, изменить имя и счёт, сменить токен, перевести в боевой режим (отдельный диалог с вводом точного имени), вернуть в песочницу, архивировать. Токен только вводится |
| Каталог | Шаблоны роботов; карточка с полями конфига (тип, обязательность, default) и JSON Schema |
| Развёртывания | Список с именами клиентов и назначений; новое — клиент, назначение, робот и форма конфига по JSON Schema шаблона; карточка — статус, текущая операция, история операций (шаг, попытка, ошибка), действия start, stop, redeploy, delete |

## Устройство

```
src/
  api/
    client.ts        fetch-обёртка: ApiError с кодом, 401 → вход, JSON в изменяющих запросах
    errors.ts        тексты ошибок по code (сырой message API не показывается)
    idempotency.ts   Idempotency-Key на попытку пользователя (Attempt, useAttempt)
    endpoints.ts     ручки API на типах @botyard/contract
    queries.ts       ключи и опции TanStack Query
    live.ts          живой статус: SSE /events/deployments с опросом как запасным путём; буфер живого лога
  schema-form/       форма по JSON Schema: разбор подмножества, значения формы ⇄ конфиг, zod-проверка, поля
  pages/             экраны
  ui/kit.tsx         кнопки, поля, диалог, таблица, бейджи
  router.tsx         маршруты (TanStack Router, code-based), проверка сессии до загрузки
```

Тесты (`bun test src`): разбор ошибок и 401 в клиенте, жизненный цикл ключа идемпотентности, форма по JSON Schema
(default, required, массивы объектов, преобразование в конфиг), условие опроса, инвалидация по событиям SSE,
переподключение потока, отсев повторов и пометка пропуска в живом логе.
