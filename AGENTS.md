# AGENTS.md — botyard/api

Бэкенд Botyard: админ-API, вебхуки Dokploy, воркер саги, outbox relay, reconciler.
Устройство системы описано в `docs/architecture.md`, план — в `docs/roadmap.md`. Перед правкой домена,
саги или машины состояний прочитать оба файла. Если поведение меняется, документ правится в том же коммите.

## Раскладка

```
src/
  modules/<модуль>/
    domain/          сущности, правила, машина состояний, порты (интерфейсы). Без Nest, без SQL, без HTTP
    application/     сценарии (use-cases): один публичный execute, оркестрация портов
    infrastructure/  адаптеры портов: Kysely-репозитории, клиент Dokploy, RabbitMQ, шифрование
    presentation/    контроллеры, DTO, guards
  shared/            то, что нужно больше чем одному модулю: конфиг, ошибки, unit of work, outbox
  main.ts            выбор процесса по PROCESS_ROLE=http|worker|relay|reconciler
migrations/          SQL-миграции Kysely, только вперёд
test/                интеграционные тесты (Testcontainers) и заглушка Dokploy
```

Зависимости направлены внутрь: `presentation → application → domain ← infrastructure`.
Сценарий не импортирует адаптер, он получает порт через DI-токен.

## Правила кода

- TypeScript strict, без `any` и без `as` для обхода типов. Ошибка — доменный класс с кодом, а не строка.
- Комментарий объясняет «почему», а не «что». У сценария и адаптера — шапка с назначением и инвариантами.
- Каждая внешняя интеграция (Dokploy, T-Invest) идёт только через свой адаптер: таймаут, retry с jitter для
  безопасных ошибок, circuit breaker на назначение. Прямой `fetch` из сценария запрещён.
- Секреты (токены T-Invest, ключи Dokploy) хранятся только зашифрованными. В логах, ошибках и аудите —
  маска. Логирование объекта целиком, в котором может быть секрет, запрещено.

## Состояние и гонки

Любая правка, которая читает и меняет состояние, перед отчётом проверяется на гонки:

- Переход статуса — условный `UPDATE ... WHERE status = $from`, результат проверяется. Ноль строк значит,
  что ход выиграл другой. Это не ошибка, а no-op.
- Одна активная операция на развёртывание: захват `active_operation_id IS NULL` условной записью.
- Внешний вызов никогда не делается внутри транзакции БД. Транзакция фиксирует результат шага и кладёт
  следующую команду в outbox.
- Таймаут или 5xx от Dokploy — неизвестный исход, а не отказ. Компенсация запускается только при
  определённом отказе.
- Вызов Dokploy, у которого нет своего ключа идемпотентности, предваряется поиском по детерминированному
  `appName` или `mountPath`.
- Повторная доставка сообщения из RabbitMQ — штатная ситуация: шаг сверяет `step` и `attempt` условной записью.
- Тест гонки — `Promise.all` двух конкурирующих сценариев или барьер в заглушке. Выигрывает ровно один,
  проигравший ничего не меняет. В отчёте о правке перечислить разобранные гонки и оставшиеся.

## Тесты

- Доменные правила и машина состояний — unit-тесты без БД.
- Сценарии с состоянием — интеграционные тесты на настоящем Postgres (Testcontainers), не на моках репозиториев.
- Клиент Dokploy — контрактные тесты на записанных ответах живого инстанса (`test/fixtures/dokploy`).
- Новый баг сначала воспроизводится падающим тестом.
