# Анализ ошибок агента

Когда применять: пользователь поправил результат, проверка или ревью воспроизводимо показали ошибку
в решении, исполнении или отчёте агента. Вызывается и сам, без отдельной просьбы, — до отчёта по задаче.

При подтверждённой ошибке собственного решения, исполнения или проверки выполнить разбор в текущей задаче.
Правка Markdown-инструкций этого репозитория для разбора разрешена без отдельного запроса; это не разрешает
менять код сверх задачи и делать Git-операции без действующего разрешения.

1. **Проверить факт:** требование, принятое решение, фактическое поведение и свидетельство (исправление
   пользователя, воспроизводимый отказ, обоснованное ревью). Смена требований, гипотеза и сбой среды
   ошибкой агента не являются. Объявленный успех при сбое среды — отдельная ошибка отчёта.
2. **Исправить результат** в рамках задачи и установить неверное предположение и отсутствовавшую проверку.
   Для повторной ошибки найти существующий урок и выяснить, почему он не сработал: ещё одна копия запрета
   эту причину не устраняет.
3. **Найти минимальное место защиты:** AGENTS.md — для обязательного триггера, навык — для решения и
   проверки, архитектурный документ — для договорённости, автоматическая проверка (тест, правило Biome,
   ограничение в БД) — для объективного инварианта. Сначала уточнить действующее правило, новое общее
   добавлять только с доказанным основанием.
4. **Записать урок** в [реестр](../../knowledge/lessons/agent-errors.md): стабильный ID, подтверждение, причина,
   изменённое правило со ссылкой, способ проверки и её результат. Похожие причины объединять. Без секретов,
   сырых логов и переписок.
5. **Проверить предотвращение:** для кода — воспроизведение до и после; для процедуры — разбор той же ситуации
   и близкого допустимого случая. Если проверен только текст правила, так и указать.

Перед похожей задачей читать в реестре только релевантные темы. Если ошибок не было, записи ради
заполнения реестра не добавлять.
