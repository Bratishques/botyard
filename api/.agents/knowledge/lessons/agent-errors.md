# Реестр ошибок агента

Порядок ведения — [error-learning](../../skills/botyard-error-learning/SKILL.md).

## DEP-API-FROM-MEMORY — API зависимости по памяти, а не по установленной версии

- **Подтверждение:** 2026-11-24, `bun run migrate` упал с `Export named 'FileMigrationProvider' not found`:
  в Kysely 0.29 миграции вынесены в отдельный вход `kysely/migration`. Код был написан по API старых версий.
- **Причина:** установились версии новее памяти модели (Kysely 0.29, NestJS 12, TypeScript 7, Biome 2.6),
  а импорт не сверили с `exports` установленного пакета.
- **Правило:** [botyard-prepare](../../skills/botyard-prepare/SKILL.md), раздел 3 — API библиотеки проверять
  по установленному пакету.
- **Проверка:** после исправления импорта миграция применилась, повторный запуск ответил `schema is up to date`.
  Предотвращение проверено только текстом правила.

## PUBLISH-UNVERIFIED-FILE — опубликован чужой текст из общего временного файла

- **Подтверждение:** 2026-11-24, владелец: описание PR #1 botyard оказалось описанием PR svelte-photo-editor.
- **Причина:** команда, которая должна была записать `pr-body.md`, была отклонена; при повторе PR открыт из
  файла с тем же общим именем, который раньше оставил другой агент в той же временной папке. Содержимое
  перед отправкой не сверялось.
- **Правило:** [botyard-verify](../../skills/botyard-verify/SKILL.md), раздел 4 — текст для публикации пишется
  в файл с уникальным для задачи именем и сверяется перед отправкой; после публикации — перечитать с GitHub.
- **Проверка:** описание PR #1 переписано из `botyard-pr1-body.md`, после PATCH перечитано с GitHub — текст
  этапа 1, упоминаний svelte нет. Предотвращение проверено только текстом правила.

## COMMIT-NOT-GATED — коммит не зависел от результата проверок

- **Подтверждение:** 2026-11-24, коммит шага 2b ушёл с 15 падающими интеграционными тестами каталога
  (TRUNCATE версий шаблонов стал невозможен из-за FK развёртываний). Найдено самим агентом до пуша.
- **Причина:** проверки и `git commit` шли в одной команде через `;` — коммит выполнялся при любом исходе.
- **Правило:** [botyard-verify](../../skills/botyard-verify/SKILL.md), раздел 1 — коммит только через `&&` после
  успешных `check` и `test:int` (или отдельной командой после просмотра их результата).
- **Проверка:** тест исправлен (`TRUNCATE … CASCADE`), коммит пересобран после зелёного прогона.
- **Повтор:** 2026-11-24, коммит шага 3c (`f633cdb`): в цепочку перед коммитом вставлена проверка индекса
  `git ls-files … | grep -c …`, после неё стояла `;`. Проверки в тот раз прошли (логи сохранены), но коммит от них
  не зависел. Уточнение правила: вспомогательные проверки (индекс, статус, подсчёты) — отдельной командой до
  коммита; в одной команде с коммитом — только `check && test:int && git add && git commit`, без `;` и без `|`.


## UNKNOWN-SWALLOWS-TYPE — в параметр `unknown` передан не тот объект

- **Подтверждение:** 2026-11-24, `DokployClient.mutate` разбирал схемой объект `Response`, а не его JSON-тело:
  `parse(method, schema, body: unknown)` принял `Response` без ошибки типов. Найдено тестом адаптера на записанной
  фикстуре `application.create` до коммита.
- **Причина:** при переносе разбора из `send` в вызывающие методы у `mutate` пропущен `await response.json()`;
  `unknown` на входе `parse` и typecheck не дали это увидеть.
- **Правило:** [AGENTS.md](../../../AGENTS.md), «Правила кода» — функция с параметром `unknown` на разбор покрывается
  тестом на настоящем значении (для Dokploy — на фикстуре живого ответа).
- **Проверка:** после исправления тест адаптера (`dokploy-deployment.platform.test.ts`) и живой контрактный тест
  зелёные; сквозной прогон воркера на песочнице Dokploy создал приложение по разобранному ответу.
