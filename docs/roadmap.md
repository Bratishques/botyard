# План

Каждый этап заканчивается работающим состоянием: тесты зелёные, README описывает, что уже можно сделать.

## Этап 0. Дизайн — готово
- Архитектура, домен, машина состояний, сага, список гонок (`docs/architecture.md`).
- Каталог из двух роботов (`bots`), dev-окружение (`infra`).

## Этап 1. Каркас и назначения
- NestJS-приложение, конфиг через zod, pino, health, `/metrics`.
- Kysely, первые миграции: `destination`, `audit_event`.
- Шифрование секретов (envelope, AES-256-GCM) с тестами.
- Адаптер Dokploy: `project.all`, `environment` (проверка ключа при добавлении), retry с jitter,
  circuit breaker и таймаут на каждое назначение.
- CRUD назначений в админ-API, вход оператора (сессия в cookie).
- CI: lint, typecheck, unit и интеграционные тесты (сервисы Postgres и RabbitMQ в CI).

## Этап 2. Клиенты, шаблоны, сага
- Миграции: `customer`, `bot_template`, `bot_deployment`, `operation`, `outbox_message`.
- Загрузка каталога из репозитория `bots`, валидация конфига по `configSchema`.
- Outbox relay → RabbitMQ, воркер шагов саги provision, команды start, stop, delete.
- Тесты гонок: двойной деплой, стоп против провижининга, повторная доставка шага.

## Этап 3. Обратная связь от Dokploy
- Вебхук `notification.createCustom` с подписью-секретом в заголовке, inbox с дедупликацией.
- Reconciler: зависшие операции, дрейф, неопубликованный outbox.
- Логи: `application.readLogs` → SSE, раздача между репликами через Redis pub/sub.

## Этап 4. Админка
- Назначения, клиенты, развёртывания (статус, история операций, логи), аудит.

## Этап 5. Витрина
- Демо-стенд: Dokploy на VPS, робот в песочнице или на симуляторе из `contest-2022`.
- README с GIF, схемами и разделом «Разобранные гонки».
- Нагрузочный прогон админ-API (k6) с честными цифрами.
